{# Shared progress-bar behavior for a long-running fan-out scan (Social Search, Company Registry). Expects the including page to have: - a
wrapping the tool's own search fields - a submit button with id="scan-submit-btn" - a hidden progress block with ids scan-progress-wrap / -bar / -count (see social.html/company.html for the exact markup) The form's own POST route runs its scan exactly as before, synchronously, and is not otherwise changed — this only adds a side channel: the browser generates a random token, submits the form via fetch() (not a native POST, so it doesn't block the page) with that token attached, and polls GET /investigate/scan-progress/ concurrently to show "N of M checked" while the real request is still in flight. When the fetch resolves with the same fully-rendered HTML the route always returned, that HTML replaces the whole page — no client-side re-implementation of result rendering needed. #}
